# server/analyzer/

The package behind the API, the MCP server and the CLI. One module per concern; a module's docstring
is its contract. Run from `server/`: `uv run python -m analyzer.<module>` runs a legacy module's
self-check; new code is tested in `../tests/`.

> **Wrap-up gate:** [`../../docs/development/checklist.md`](../../docs/development/checklist.md), the ORM and DB
> section first: the models ARE the schema (a change is a model edit plus an autogenerated Alembic
> revision), SQLAlchemy through the `db.py` bridge, the pinned raw-SQL carve-outs, the three files.

## Map

**Ingest and extraction.** `harness.py` sniffs which coding harness wrote a transcript and normalises
it to Claude Code's event shape (adding a harness is one `detect()` clause and one adapter; see
`../../docs/harnesses.md`). `ingest.py` walks a transcript into a session (counts `session_metrics`
here, the only place raw usage exists). `redact.py` is the pure, stdlib-only redactor, copied byte for byte into `csa-plugin/scripts/`
(`tenant.redaction_policy` reads the workspace floor applied on top of the client's redaction). `extract.py` calls the LLM for facts; `harvest.py` finds deterministic evidence without one.
`queue.py`, `etl.py`, `drain_loop.py` and `incremental.py` are the deferred pipeline (`/api/ingest`
always queues; the ETL drains per org). `llm.py` is the one provider seam (`claude -p` when the image has
it, else HTTPS with an API key).

**Storage.** `models.py` and `tenant.py` hold the schema itself (corpus, `tel` telemetry, control
plane); `migrations.py` plus `../migrations/` are the three Alembic environments that put it on disk,
one `ensure()` per open. `store.py` owns the writers (`load_sqlite`, `refresh_facts`, `build_fts`,
`write_entity_stats`); `db.py` is the permanent bridge that runs statements on the caller's connection. `orgs.py` is
the control plane (orgs, tokens, invites, workspace requests, `is_multi_tenant`). `tenant.py` is
per-org config. `archive.py` keeps transcripts (`tenant_config.archive_days` per workspace, `forever` = keep until deleted).
`backup.py` snapshots an org's files.

**Serving.** `search.py` is FTS plus rerank; `route.py` classifies a question (self, person, team,
locate); `ask.py` plans SQL when a question is relational; `resolve.py`, `fuzzy_*.py`
resolve loose identifiers; `gql.py` is the GraphQL schema (query-only, transcript reader inside);
`pagination.py` pages it. `signals.py` records what recall served and whether it was acted on;
`tracer.py` writes spans.

**Quality.** `judge.py` labels facts (initial pass plus a staleness pass), `dedup.py` clusters
paraphrases, `verify.py` checks facts against registries, `entity_gate.py` and `entity_types.py`
decide which entities are served and what the taxonomy is, `improve.py` counts per-session cost and
waste and turns repeats into project rules, `budget.py` caps spend per org.

**Identity.** `auth.py` is the gate (`identify`, `current_mode`, `google_*`), `cliauth.py` the
device flow and the browser login, `fleet.py` the directives a server sends to clients,
`project.py` the cwd-to-repo normalisation, `memories.py` the Claude Code memory files.

## Rules that bite here

- A write holds the file's only writer lock: compute, then `BEGIN`, write first, commit. Never
  `BEGIN IMMEDIATE` on a `store.sqlite_db` connection (it takes every attached file).
- A table belongs in the corpus only if a question is answered from it; anything the serving path
  writes on every request goes in `telemetry.db`.
- New text that reaches SQLite or FTS from a raw session passes `redact.redact()` first.
- `sessions.user` is whose work it is; `sessions.shipped_by` is who may delete it. Do not conflate them.
- `/api/forget` is shipper-or-workspace-admin, `transcript` reads are owner-or-workspace-admin,
  both scoped to the org's own database file.
