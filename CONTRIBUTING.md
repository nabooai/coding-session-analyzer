# Contributing to CSA

Thanks for looking. This page gets you from a clone to a green test run and an open pull request.
How the pieces fit is in [docs/architecture.md](docs/architecture.md).

## Set up

You need Python 3.12 with [`uv`](https://docs.astral.sh/uv/), Node 20 or later with npm, and Go 1.22
or later.

```bash
# server
cd server
uv sync
uv run python apiserver.py          # http://127.0.0.1:8766, auth off because it binds loopback only

# web UI, in a second terminal
cd server/ui
npm ci
npm run dev                         # Vite dev server; `npm run build` writes ui/dist, which apiserver.py serves

# client
cd client
go build -o csa-client .
```

The server keeps its data in `server/data/` (gitignored). Extraction needs a model: with none
configured, sessions queue and nothing is extracted, which is enough for most UI and API work. For a
realistic box with two seeded workspaces, an admin and an invite, run
`.claude/skills/scratch-server/scratch.sh /tmp/csa-box 8794` from the repo root. It recreates the box
directory, prints the invites and demo accounts, and needs no Claude Code.

## Run the checks

Run the checks for every component you touched before opening a pull request.

| Component | Lint and types | Tests |
|---|---|---|
| `server/` | `uv run ruff check .` | `uv run python -m pytest tests/ -q` |
| `server/ui/` | `npm run check` (tsc, eslint, vitest) | `npm test`, then `npm run build` |
| `client/` | `gofmt -l .` prints nothing, `go vet ./...` | `go test ./...` |
| `research/` | | `uv run --project server python research/run.py --selfcheck` (from the repo root) |

Some older modules in `server/analyzer/` keep a `__main__` self-check: if you change one, run
`uv run python -m analyzer.<module>` from `server/` as well.

A schema change is a model change plus an autogenerated Alembic revision, read by hand and committed
together. See [docs/development/schema-migrations.md](docs/development/schema-migrations.md).

## Conventions

These come from review on this repository. The full ledger, with the review comments behind each
rule, is [`.claude/skills/pr-code-review/HUMAN_REVIEW_CONVENTIONS.md`](.claude/skills/pr-code-review/HUMAN_REVIEW_CONVENTIONS.md).

- **No new environment variables.** Settings are rows (`server/analyzer/tenant.py` `_FIELDS`), shown
  on Admin > Settings and editable with `csa.py org config`. The environment carries bootstrap values
  and secrets only. A PR that needs a new `CSA_*` variable says why.
- **No compatibility shims.** No aliases for old config values, no deprecation windows. Change it and
  say so in the release note.
- **A docstring states the contract, nothing more.** No comments that restate the line below, tour the
  algorithm, or point at the PR a line came from.
- **Asserts belong in tests**, not in production modules.
- **Plain values over plumbing.** Direct indexing over `(x or {}).get()` chains and dict merges; no
  module constant for every string.
- **Durable state lives in a table**, never in a module-level dict, list or set.
- **Typed SQLAlchemy models** (`Mapped[...]`, `mapped_column`); raw SQL only at the pinned carve-outs
  in `server/tests/test_no_raw_sql.py`.
- **Absolute imports and `pathlib` paths.**
- **Standard library first.** A new dependency needs a stated reason; the client has none at all.
- **User-facing copy is short** and uses no em or en dashes. Every claim on the public landing names
  the file or route that makes it true ([docs/development/landing-copy.md](docs/development/landing-copy.md)).
- **New text that reaches storage from a transcript passes `redact.redact()` first.**

Before you start in an area, read the page for it in [docs/development/](docs/development/README.md):
SQLite writer locks, settings, the web UI and the others each have a trap that is not obvious from the
code. The [change checklist](docs/development/checklist.md) is what a change owes before it is done.

## Pull requests

- Branch from the latest `origin/master` with a plain short name and keep one logical change per branch.
- The PR body says what changed, why, and how you verified it. A visible UI change includes
  screenshots in light and dark themes and at 390px wide.
- Keep the diff to what the change needs; send unrelated cleanups separately.

## Working with Claude Code

This repository is developed with Claude Code, and `.claude/` holds the skills, review agents and
hooks that make those sessions repeatable (a lint and test gate on `gh pr create`, the checklist at
session start). None of it is required to contribute. See
[docs/development/agent-workflow.md](docs/development/agent-workflow.md).

## Security issues

Do not open a public issue for a vulnerability. See [SECURITY.md](SECURITY.md).
